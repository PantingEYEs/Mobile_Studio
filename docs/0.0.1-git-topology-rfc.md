# Mobile Studio RFC: Git 分支拓扑可视化技术预案与数学建模 (Rev. 2)

> 本文为 Issue #5 的深度技术方案与可行性论证，系统阐述技术栈选型、GPU/图形库辩证、业界参考项目及拓扑渲染的数学算法基础。

---

## 一、技术栈选型与 GPU/Shader 语言可行性辩证

### 1. 基础开发语言评估
- 结论：坚守「Go + Svelte」是 Android 15 + Termux 宿主下的最佳技术搭配。
- Go 语言通过系统级管道调用原生 git，以微秒级延迟输出拓扑，单二进制静态编译，内存占用 < 25MB。
- Svelte 属于编译期框架，无 Virtual DOM 开销，输出代码极度精简，最适合移动端高能效比运行。

### 2. 是否应该引入 GPU 语言 (WebGL / WebGPU / GLSL / WGSL)？
结论：绝对不要引入。在 Git 拓扑图场景下，使用 GPU 编程不仅无益，反而是严重的负优化陷阱。

- 场景严重错位：
  GPU 擅长处理数十万几何顶点、3D 网格、流体光影或粒子系统。而 Git 提交记录在手机单屏幕视口内仅有 15 ~ 30 行，属于典型的「低几何密度、高文本密度」信息流。现代浏览器渲染 30 根矢量曲线耗时低于 0.5ms，算力完全过剩。
- 文本排版灾难（尤其是中文字体）：
  Git 拓扑中 80% 的信息量是文本（提交信息、作者、分支 Tag、Hash）。GPU 原生缺乏字符排版能力，渲染文字必须在内存中构建巨大的 SDF (Signed Distance Field) 字模纹理，面对上万个汉字极其消耗显存，且无法支持系统字体无级缩放、Emoji 渲染与用户长按选词复制。
- 交互与事件模型完全降级：
  SVG 节点天生自带标准的 DOM 事件与 CSS 动画；而 WebGL 画布上仅为扁平位图，为了实现点击节点、悬停高亮，必须手动手写光线拾取 (Raycasting) 或空间索引反算坐标，属于重复造低效轮子。
- 功耗与显存开销：
  移动端开辟 WebGL 上下文默认增加 30MB+ 独立显存开销，持续重绘会导致处理器锁高频、电池断崖式掉电；而 SVG 方案在静止状态下 CPU/GPU 占用率为零。

### 3. 最终渲染架构定调
采用「Svelte + 原生矢量 SVG (三阶贝塞尔轨道) + DOM 文本混排 + CSS 硬件加速合成」。
Android 15 内核（Chromium/Blink）底层已自动通过 Vulkan 与 Skia 对 SVG 进行硬件加速，画质在高清视网膜屏上永不失真。

## 二、业界成熟项目参考与启发

1. IntelliJ IDEA / Android Studio (vcs-log 模块)
   - 经典布局架构：首列固定宽度多色矢量连线，后续列按需对齐分支徽标、信息、作者与 Hash。
2. VS Code Git Graph (mhutchie/vscode-git-graph)
   - 基于 TypeScript + SVG 的纯前端拓扑，贝塞尔曲线轨道弯曲与颜色池算法是业内公认最优雅的实现。
3. GitUp (Mac 原生客户端)
   - 启发了以「边交叉最小化」为优先级的图谱降维算法，使复杂分支在横向上保持紧凑。
4. tig (Linux CLI)
   - 证明了基于有向无环图的单趟流式扫描可以在 O(N) 复杂度内完成轨道分配。

## 三、拓扑排版算法的数学依据与模型设计

Git 的版本演化在数学上是一个严格的有限、单向、有向无环图 (Directed Acyclic Graph, DAG)。将其投影到二维屏幕（垂直时间轴 + 水平泳道轴）依赖以下数学定理与算法：

### 1. 偏序关系与拓扑排序 (Topological Sorting)
- 数学定义：若提交 A 是提交 B 的祖先，则在 DAG 中存在单向连通路径 B -> A。在时间轴投影中，子提交必须严格出现在其父提交上方。
- 算法实现：调用系统级 git log --topo-order --all，确保遍历时任意节点在其所有子节点之后、父节点之前被访问。

### 2. 泳道分配与区间图着色 (Interval Graph Coloring / Register Allocation)
- 数学等价性：分支生命周期在垂直轴上表现为连续的「生存区间 (Live Range)」。给多分支分配水平列号 (Lane)，等价于编译原理中的寄存器分配问题与图论中的区间图着色。
- 线性扫描贪心算法 (Linear Scan Allocation)：
  1. 维护活动泳道槽位数组 activeLanes，存储各列当前预定追踪的父节点 Hash。
  2. 遍历到提交 C 时，若已在某列预定则继承列号，否则分配首个空闲槽位。
  3. C 的第一父节点沿用本列，合并操作涉及的次级父节点分配相邻空列。当某父节点的全部入边均连接完毕时，立即释放槽位供后续分支复用，使横向列数严格压制在最小色数范围内。

### 3. 三阶贝塞尔曲线平滑几何学 (Cubic Bézier Geometry)
为消除生硬折线，在分叉点 (x1, y1) 与目标点 (x2, y2) 之间使用三阶参数曲线：
P(t) = (1-t)^3 * P0 + 3(1-t)^2 * t * P1 + 3(1-t) * t^2 * P2 + t^3 * P3
其中第一控制点取 (x1, y1 + dy/2)，第二控制点取 (x2, y1 + dy/2)。
两端一阶导数在时间轴上保持垂直，曲率连续自然，完美还原 Android Studio 与 GitKraken 标志性的平滑轨道。

## 四、补充工程关键细节

1. 零截断通信协议 (Null-Byte Protocol)
   提交信息中常包含双引号、换行符、反引号及各类特殊符号。后端调用 git log 时采用 ASCII 零字节 (%x00) 分隔字段、记录分隔符 (%x1e) 分隔提交，彻底杜绝字符串转义与 JSON 注入漏洞。
2. 视口虚拟滚动 (Virtual Scrolling)
   面对上千次提交的大仓库，前端通过计算当前滚动高度，仅动态挂载视口内可见的 20~30 个 DOM 节点，使内存与帧率与提交总量脱钩。
3. OLED 暗色系调色盘 (Theme Palette)
   针对三星 AMOLED 屏幕适配高对比度霓虹色系（天蓝 #60a5fa、薄荷绿 #34d399、珊瑚粉 #f472b6、琥珀黄 #fbbf24、紫罗兰 #a78bfa），保证分支交错时的视觉辨识度。
